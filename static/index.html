測試模組 01：實機極限測速 (Throughput Speedtest & iPerf3)

功能、目的、雙向頻寬評估標準與「物理速率 vs 真實吞吐量」核心定律

收合/展開
🎯 測試功能與診斷目的
  • 測試目的：評估在特定空間距離與實體天線阻隔下，基地台至用戶端手機/電腦之間「真實可用的應用層雙向 TCP 頻寬上限」。
  • 測試功能： ▸ 瀏覽器雙向測速 (Zero-Install)：手機掃描 QR Code 連線後，免裝任何 App，直接透過 HTTP 串流精確測量下載（基地台➔手機）與上傳（手機➔基地台）實測 Mbps。 ▸ iPerf3 專業伺服器 (連接埠 5201)：支援在背景一鍵啟用，供進階網路工程師透過終端機指令或專業 App 進行多執行緒 (Multi-stream) 極限壓力測試。
📊 診斷指標與判讀標準 (以 5GHz 20MHz 頻寬為例)
110 ~ 135 Mbps極佳：符合 MCS 8 理論淨頻寬上限，射頻傳輸無干擾
70 ~ 110 Mbps良好：中等距離或輕微隔間衰減，足以滿足 4K/8K 串流
30 ~ 70 Mbps普通：隔多道牆，網卡已自動降階至 MCS 2~4
< 30 Mbps偏低：空氣中有嚴重同頻干擾，或超出有效涵蓋範圍

💡 上傳通常低於下載？ 手機為節省電池，射頻發射功率通常僅有 10~15 dBm，遠低於 ALFA 外接天線的 23~30 dBm，因此手機上傳速率略低於下載屬正常物理現象。

🛠️ iPerf3 終端機測試操作指引
# 在用戶端手機（Termux 或 iPerf App）或筆電執行測試：
iperf3 -c 10.42.0.1 -t 10 -P 4
參數說明：-c (伺服器 IP), -t (測試秒數), -P 4 (4 條平行資料流全力壓測)

測試模組 02：Ping 延遲與抖動 (Ping Latency & Jitter)

功能、目的、往返時延 RTT 評量標準與抖動對即時語音電競的影響

收合/展開
🎯 測試功能與診斷目的
  • 測試目的：評估無線空氣介質傳輸的「反應時間（時延）」與「連線穩定度（波動性）」，檢驗有無突發電磁干擾或封包遺失。
  • 測試功能：自動帶入已連線手機的 IP 位址（如 `10.42.0.254`），連續發射 ICMP 探測封包，精確統計出最小、平均、最大往返時間（RTT）、抖動波動值與封包遺失率。
📊 延遲與抖動判讀標準
延遲 < 5 ms
電競級表現：近距離無障礙，空中介質極度潔淨。
延遲 5 ~ 15 ms
優良水準：日常網頁瀏覽、串流影音完全無感。
延遲 > 50 ms / 抖動高
異常警訊：空間中有同頻強干擾，或手機處於弱訊號邊緣。
🛠️ 命令列即時 Ping 探測
ping -c 20 10.42.0.254

測試模組 03：即時訊號折線圖 (Live RSSI & Rate Adaptation)

功能、目的、雙軸動態監控與手持走動漫遊衰減測試

收合/展開
🎯 測試功能與診斷目的
  • 測試目的：手持手機在辦公室或住家不同房間走動時，動態觀測實體障礙物（水泥牆、鐵門）與距離對電磁波造成的路徑損耗（Path Loss），檢驗天線涵蓋無死角。
  • 測試功能：工作台每秒精確擷取連線裝置的訊號強度（RSSI dBm）、雙天線數值、MCS 調變階梯、即時 Tx/Rx 協商速率與重傳次數，繪製成即時雙軸折線圖。
📊 RSSI 接收強度階梯標準
-30 ~ -50 dBm極佳：基地台近距離，鎖定最高 MCS 8 (173.3 Mbps)
-50 ~ -65 dBm良好：日常最佳工作區間，維持全速運作
-65 ~ -75 dBm普通：漫遊降速臨界點，開始降階為 MCS 4~6
-75 ~ -85 dBm微弱：隔水泥牆，降至低階調變以抵抗雜訊
< -85 dBm斷線邊緣：封包重傳飆升，即將中斷交握

sudo iw dev wlx00c0cabb0b45 station dump

測試模組 04：通訊協定與封包 (Protocols & Packet Inspection)

功能、目的、tcpdump 實戰指令庫與 Wi-Fi 連線全生命週期協定排查

收合/展開
🎯 測試功能與診斷目的
  • 測試目的：深度檢視手機連入熱點後「從配發 IP 到正常上網」的完整通訊行為，排除「連得上 Wi-Fi 卻無法上網」、「一直卡在取得 IP」、「DNS 解析卡頓」或「跳不出認證網頁」的真正根因。
  • 測試功能：透過 Linux 原生 `tcpdump` 工具直接在射頻介面 (`wlx00c0cabb0b45`) 上側錄，涵蓋 DHCP DORA、DNS/DoT、ARP、Captive Portal 204、mDNS、NTP 與 QUIC 流量，並支援匯出 PCAP 檔供 Wireshark 離線鑑識。
🛠️ 實戰 tcpdump 快速側錄指令庫 (終端機直接複製執行)
1. 側錄 DHCP 四向交握 (排查卡在「正在取得 IP 位址」) UDP 67/68
sudo tcpdump -i wlx00c0cabb0b45 -n "port 67 or port 68" -v
▸ 觀察 DORA 流程：Discover ➔ Offer ➔ Request ➔ ACK 是否完整配發 IP 與閘道。
2. 側錄上網連通性探測與強制門戶檢測 (Captive Portal Detection) HTTP 204
sudo tcpdump -i wlx00c0cabb0b45 -n "tcp port 80 and (tcp[tcpflags] & tcp-push != 0)"
▸ 觀察 Android (`generate_204`) 與 Apple (`hotspot-detect.html`) 的上網探測請求；若未收到 204 或遭遇重導向，手機會跳出「驚嘆號」或自動彈出認證網頁。
3. 側錄區域網路設備自動發現 (AirPlay / Chromecast / 智慧家庭) mDNS / SSDP
sudo tcpdump -i wlx00c0cabb0b45 -n "udp port 5353 or udp port 1900"
▸ 檢測手機是否持續向多點傳送位址 (`224.0.0.251` / `239.255.255.250`) 廣播尋找投影設備或區域網路印表機。
4. 側錄現代 Google / YouTube 之 QUIC (HTTP/3) 串流 UDP 443
sudo tcpdump -i wlx00c0cabb0b45 -n "udp port 443" -c 30
▸ 現代影音串流大多採用 UDP 443，具備 0-RTT 快速重連與抗弱訊號連線遷移特性。
5. 完整封包側錄並儲存為 PCAP 檔案 (供 Wireshark 深度鑑識) *.pcap
sudo tcpdump -i wlx00c0cabb0b45 -w /tmp/wifi_diagnostic.pcap -c 1000
▸ 將擷取的 1000 個封包直接存檔，可用 Wireshark 打開進行時間軸與協定層次圖形化分析。
📊 連線故障排查實務情境判讀
  • DNS 失敗 (Port 53)：若手機送出 DNS Request 卻遲遲沒有收到 DNS Response，代表本機 NAT 轉送中斷或上游 DNS 伺服器無回應。
  • ARP 風暴或 IP 衝突：若看到同一 IP 持續在區網發送大量的 ARP Request，代表有兩台設備被配發了相同 IP。
  • NTP 校時異常 (Port 123)：若設備本機時間與基地台相差過大，會導致所有 HTTPS 網站跳出憑證無效警告。

測試模組 05：頻段抗干擾 (RF Band & Channel Comparison)

功能、目的、頻段特性評估與最佳頻道規劃

收合/展開
🎯 測試功能與診斷目的
  • 測試目的：評估周遭環境 2.4GHz、5GHz 與 6GHz 頻譜的電磁波擁擠程度，避開同頻干擾與鄰頻干擾，引導挑選最潔淨之頻道。
  • 測試功能：提供不同頻段之發射功率、頻寬上限與干擾對比表，並能即時切換 ALFA 網卡至不同頻道進行抗干擾對比實測。
📊 現場抗干擾頻道規劃最佳指引
  • 2.4GHz 頻段：絕對只使用 Ch 1、Ch 6 或 Ch 11（唯三完全互不重疊的乾淨頻道）。切勿使用 Ch 2~5 或 7~10，否則會同時遭受左右兩側頻道的非對稱同頻干擾！
  • 5GHz 頻段：優先選用 UNII-1 (Ch 36~48) 或 UNII-3 (Ch 149~165)。無需等待 DFS 雷達避讓，發射功率充足且頻譜極為乾淨。

第二篇：Wi-Fi 射頻與通訊核心理論知識庫

核心理論 01：空中介面（Air Interface / OTA）與電磁波訊號本質

空中介面由來、dBm 負對數毫瓦換算、RSSI 接收階梯與 2T2R MIMO 雙天線

收合/展開
什麼是空中介面（Air Interface / Over-The-Air, OTA）？
在電腦網路中，傳輸媒介分為「有線」與「無線」。有線網路（雙絞線、光纖）具有封閉且高度隔離的實體傳導通道；而無線通訊（Wi-Fi、行動網路）則是將電氣訊號轉換為高頻電磁波，以開放共享的空氣作為傳播媒介。由於空氣中充滿了各種電磁雜訊與反射阻擋，因此「空中介面」的物理特性直接決定了連線品質。
💡 名詞比較：中國大陸普通話常將其簡稱為「空口」，而在臺灣正體中文通訊與電信規範中，標準學術與工程術語皆為「空中介面」。
1. 接收訊號強度指標 (RSSI, dBm)

單位為 dBm（毫瓦分貝），為負數對數標度。因為接收到的電磁波能量極其微弱（通常只有毫瓦的百萬分之一）： 0 dBm = 1 mW | -30 dBm = 0.001 mW | -60 dBm = 0.000001 mW

-30 ~ -50 dBm極佳（基地台旁，最高調變速率）
-50 ~ -65 dBm良好（高速上網、極限測速推薦）
-65 ~ -75 dBm普通（漫遊臨界點，網卡開始降速）
-75 ~ -85 dBm微弱（容易出現封包重傳與延遲抖動）
< -85 dBm斷線臨界（難以維持交握）
2. 2T2R 雙天線架構 (MIMO & Ant 1 / Ant 2)

ALFA AWUS036AXML 配備兩支外接大天線，硬體為 2T2R（2 Transmit, 2 Receive，雙發雙收）：

  • 空間多工 (Spatial Multiplexing)：同時發射 2 條不同的資料空間流（Spatial Streams, NSS=2），理論頻寬直接翻倍。
  • 分集接收 (Rx Diversity)：兩支天線相隔一定距離，接收不同相位反射波，當一支天線陷入衰落（Fade）時，另一支天線仍可完整還原訊號。
  • 波束成形 (Beamforming)：透過調節兩支天線的相位差，將電磁波能量聚焦朝向用戶端手機方向發射。

核心理論 02：物理層速率 (PHY Rate) vs 真實測試吞吐量 (Throughput)

半雙工機制、CSMA/CA 載波偵聽、802.11 協定層層開銷與 60%~70% 黃金折損定律

收合/展開

工程常見疑惑：「為什麼手機 Wi-Fi 狀態顯示連線速率為 173.3 Mbps（或 866 Mbps），但在本測速台或 Speedtest 實測卻只有 120~135 Mbps？」

💡 Wi-Fi 頻寬折損的三大物理定律：
  1. 半雙工機制 (Half-Duplex) 與空中介質爭用： Wi-Fi 不像有線網路線（雙絞線內部分離的 Tx/Rx 銅線）能同時全雙工收發。Wi-Fi 在同一個頻道上同一時間只能「要麼發射、要麼接收」，且必須遵循 CSMA/CA (載波偵聽多重存取/碰撞避免) 協定——發送前必須先監聽空氣中是否有其他設備在說話，若有則需隨機「退避等待」(Backoff)。
  2. 802.11 協定層層開銷 (Protocol Overhead)： 傳輸資料時，實際 Payload 必須被包覆在物理層前導碼 (Preamble)、MAC 標頭、WPA 密碼學加密標記、TCP/IP 標頭之內；且每個發送出去的資料訊框，接收方都必須回傳一個實體層 ACK (確認封包)。
  3. 訊框間隔保護 (Inter-Frame Spacing)： 為了防止多徑反射（Multipath Reflection）訊號自身重疊干擾，封包與封包之間強制保留 SIFS、DIFS 與保護區間 (Guard Interval, 800ns/400ns)。
📌 工程換算黃金法則：
真實世界的 Wi-Fi TCP 最大淨吞吐量 (Net TCP Goodput) ≈ 物理層協商速率 (PHY Rate) × 60% ~ 70%。
例：VHT-MCS 8 (173.3 Mbps) × 0.70 ≈ 121.3 Mbps（與本工作台實測完美吻合！）。

核心理論 03：MCS 調變編碼等級與動態速率調適 (Rate Adaptation)

QAM 星座圖載貨密集度、Minstrel 演算法與走動降速保全連線機制

收合/展開

什麼是 MCS (Modulation and Coding Scheme)？
MCS 是 Wi-Fi 定義的一組「數位調變方式」與「前向錯誤更正編碼率（FEC Coding Rate）」的組合代碼。 調變就像「裝載貨物的密集度」：

高階調變 (256-QAM)
每個符號攜帶 8 bits 資料。速度極快，但需要訊號極度乾淨（高 SNR），稍微有一點雜訊就會解碼錯誤。
中階調變 (16/64-QAM)
每個符號攜帶 4~6 bits。兼顧速度與一定程度的抗雜訊能力。
低階調變 (BPSK/QPSK)
每個符號只攜帶 1~2 bits。傳輸速度慢，但在訊號極弱（-80 dBm）甚至雜訊極大時依然能正確解析。
📈 為什麼走動時「即時訊號折線圖」會看到速率階梯式變化？
這就是無線晶片內部的 動態速率調適演算法 (Rate Adaptation Algorithm, 如 Minstrel)： 當手機遠離基地台時，硬體偵測到訊號衰減、雜訊比變差或 ACK 逾時重傳增加，驅動程式會主動放棄高階 MCS，降速至低階 MCS，寧可犧牲傳輸速率，也要保證封包成功抵達、連線絕不中斷！

收合/展開

深入探討：為什麼隨身 USB 網卡在 Linux 核心無法發射 6GHz AP？

在嘗試啟動 6GHz AP 時會出現 Frequency 6135 not allowed for AP mode, flags: 0x10003 NO-IR。 這是因為各國通訊傳播委員會（美國 FCC、臺灣 NCC）：

  • 保護既有微波通訊設施：6GHz 頻段原先已被衛星地面站、公用事業微波骨幹長年使用。
  • 標準功率 (SP) 與低功率室內 (LPI) 規定： 固定的室內 AP 必須向 AFC（自動頻率協調）雲端資料庫註冊地理位置，確保不干擾微波電台；而像 ALFA 這類隨插即拔的可攜式 USB 網卡，被法規強制定義為「用戶端從屬裝置 (Client Station)」，絕對禁止私自進行主動射頻輻射（NO-IR: No Initiating Radiation）。
  • 正確使用 6GHz 的診斷方式：在 Linux 下，ALFA 網卡可全力作為 6GHz Client 連線，或進入 Monitor Mode 進行空中封包監聽！

核心理論 05：延遲 (Latency)、抖動 (Jitter) 與封包重傳 (Retries)

往返時延 RTT、Jitter 緩衝區爆滿、手機省電喚醒特徵與撞包重傳

收合/展開
1. 往返延遲 (RTT / Ping)

指封包從發送端抵達接收端，再收到回應的完整來回時間。 優良的 Wi-Fi 空中傳輸延遲應落在 2 ~ 8 ms。如果超過 30ms，通常代表空氣中有嚴重碰撞或網卡開啟了激進省電模式。

2. 延遲抖動 (Jitter)

連續封包之間延遲時間的「浮動變化標準差」。 對於即時線上遊戲、VoIP 網路電話與視訊會議而言，抖動比延遲本身更具破壞性，高抖動會導致 Jitter Buffer 爆滿或欠載，引發音訊破音或遊戲畫面瞬間瞬移。

3. 封包重傳 (Tx Retries)

當發送端把資料丟出去，但在指定時間內沒有收到接收端的 ACK 回應時，硬體晶片會立刻自動重發。 重傳次數飆高代表空間中有強干擾源（如藍牙、其他 AP）撞包，會嚴重吃掉空氣頻寬。

💡 手機省電模式 (Power Save) 的第一個 Ping 陷阱：手機休眠時 Wi-Fi 晶片會進入低功耗監聽狀態，收到第一個封包喚醒時常需 50~80ms，第二個封包即恢復為 3ms，此為省電特徵而非網路故障。

核心理論 06：Wi-Fi 安全防護、802.11 原生訊框與空中側錄鑑識

802.11 原生訊框光譜、WPA2 vs WPA3 前向保密性與 Wireshark 顯示過濾器

收合/展開
🔬 封包側錄的兩種維度：AP 介面側錄 vs. 空中監聽模式 (Monitor Mode)

在無線通訊中，網卡處於不同模式時側錄到的內容有本質上的不同：

1. AP 介面側錄 (本工作台模式)
網卡晶片已將空中電磁波解調、解密並轉為標準乙太網路訊框（Ethernet Frame）。此模式聚焦於 Layer 3/4 網路層與傳輸層行為（IP、TCP/UDP、DHCP、DNS、HTTP、TLS），適合排查上網連線與服務狀態。
2. 空中監聽模式 (Monitor Mode)
網卡處於混雜空中監聽，能直接擷取所有 802.11 Layer 2 原生無線訊框（RadioTap Header、管理訊框、控制訊框、交握訊框），無需連線或密碼即可側錄空中電波。
📡 802.11 原生空中管理、控制與交握訊框全光譜
類型 訊框名稱 (Frame) 空中物理行為與診斷用途
管理訊框 Beacon (信標訊框) AP 每約 100ms 固定廣播，公告 SSID、頻道寬度、加密方式、國別碼與 WMM QoS。
管理訊框 Probe Req / Resp 手機尋找已知 Wi-Fi 時主動在空中發送探測請求，AP 收到後回覆能力與訊號強度。
管理訊框 Auth / Association 設備加入熱點的二階段交握：開放認證 (Auth) ➔ 關聯請求 (Assoc Req) ➔ AP 配發 AID (Assoc Resp)。
管理訊框 Deauthentication 設備主動離開或中斷連線；在資安鑑識中，若空中出現海量 Deauth 代表遭遇惡意斷線攻擊。
控制訊框 RTS / CTS 發送大型資料前先預約空中通道，專門用於徹底解決「隱藏節點 (Hidden Node)」互撞問題。
控制訊框 Block ACK / ACK 接收端收到資料後回傳之實體確認訊框，未收到則觸發發送端硬體自動重傳。
安全交握 EAPOL (4-Way Handshake) WPA2/WPA3 密碼交握訊框，雙方在不傳輸明文密碼的前提下安全衍生動態會話金鑰 (PTK)。
WPA2-Personal (PSK) 的致命弱點

採用 4 向交握（4-Way Handshake）。攻擊者只要在空中側錄到手機連線時的 4 個 EAPOL 訊框，就能將雜湊帶回電腦使用高效能 GPU 進行無限制的「離線字典暴力破解」，只要密碼在字典中即宣告失守。

WPA3-Personal (SAE Dragonfly) 前向保密

強制導入 SAE (同時對等驗證)，基於零知識證明與橢圓曲線密碼學，每次交握皆獨立動態生成暫時金鑰，具備「前向保密性 (Forward Secrecy)」——即使空中封包全被側錄，也絕對無法透過離線字典算回密碼！
